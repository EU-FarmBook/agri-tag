# API Endpoints Overview

This service exposes **4 `POST`** classification endpoints and **4 `GET`** informational
endpoints (plus FastAPI's auto-generated `/docs` Swagger UI). They differ mainly in the
**input type** (file vs URL vs media), the **processing path** (heuristics + vision vs
text-only vs transcript-only), and whether they **return a classification or metadata**.

## Quick comparison

| Endpoint | Method | Input | What it does | Processing path | Returns |
| --- | --- | --- | --- | --- | --- |
| `/classify` | `POST` | Uploaded file (`.pdf`, `.docx`, `.pptx`, `.txt`, `.csv/.tsv/.xlsx`, images, audio, video) | Full category + subcategory classification of an uploaded asset | Deterministic heuristics, **OCR fallback** (scanned PDFs/images), **vision LLM** (PDFs/images), audio/video transcription + frame sampling, optional text LLM, fusion | Ranked subcategory, evidence, rationale, fusion + routing, **topics**, **intended_purposes** |
| `/classify-url` | `POST` | JSON `{ "url": "https://…" }` | Classifies a public web page / document URL | **Text-only**: PageSense extraction → heuristics → optional text LLM. **No OCR, no vision** | Same response shape as `/classify`, with URL extraction + cache metadata |
| `/classify-text` | `POST` | JSON `{ "text": "…" }` | Classifies a raw text snippet (no upload) | **Text-only**: treated as a text document → heuristics + optional text LLM, topics, intended purposes. **No OCR, no vision**. Capped at ~5000 words (10 A4 pages) | Same response shape as `/classify`; `category_used` is `Document` |
| `/classify-media-llm` | `POST` | Uploaded audio/video file | Transcript-first subtype classification of media, **text LLM only** | Media transcription → text LLM (no heuristics fusion, no vision) | Ranked subtype candidates, optional transcript |
| `/` | `GET` | — | API info / capability discovery | none | Name, version, features, supported file types, links |
| `/health` | `GET` | — | Liveness + model/backend readiness | none | Status, per-model `configured`/`enabled` flags, media tooling readiness |
| `/subcategories` | `GET` | — | Returns active subcategory definitions + criteria | none | Subcategory metadata, detectable features, criteria |
| `/intended-purposes` | `GET` | — | Returns the intended-purpose (user-intent) taxonomy | none | Purposes list, grouped by category, `max_selected_per_asset` |
| `/docs` | `GET` | — | Interactive Swagger UI (auto-generated by FastAPI) | none | HTML |

## Output cardinality

The classification axes are returned with fixed cardinality:

| Axis | Count | How produced |
| --- | --- | --- |
| `category_used` | exactly 1 | deterministic MIME/file-type routing (no LLM) |
| subcategory (`all_candidates`) | 1, or 2 if the runner-up is close | measurable heuristics + optional LLM(s), fused |
| `topics` | 1–3 | lexicon + sentence-transformers embedding (no LLM) |
| `intended_purposes` | 1–3 | sentence-transformers embedding + optional LLM |

## How the `POST` endpoints differ

The classification endpoints are **not interchangeable** — pick by input type:

- **`/classify`** is the full pipeline and the only path that runs **vision** and **OCR**.
  Use it for uploaded documents, datasets, images, audio, and video. It exposes the full
  set of tuning parameters (`fusion_strategy`, `heuristics_alpha`, `vision_max_pages`,
  `ocr_max_pages`, model-routing toggles, Agri Gate).
- **`/classify-url`** stays **text-only after PageSense extraction**. OCR and vision routing
  do not apply because the service only ingests PageSense's extracted text, not the raw
  bytes behind the URL. It can route into `Document`, `Dataset`, or `Software Application`.
- **`/classify-text`** takes a **raw text snippet** (no upload) and treats it as a text
  document — heuristics + optional text LLM, plus topics and intended purposes. No OCR or
  vision. Capped at ~5000 words (10 A4 pages); `category_used` is always `Document`.
- **`/classify-media-llm`** is a **transcript-first, text-LLM-only** shortcut for audio/video.
  It skips the heuristic/vision fusion machinery and requires both the text LLM and the media
  transcriber to be configured (returns `503` otherwise).

## Provider selection (`provider=custom|mistral`)

All four `POST` endpoints accept a `provider` query parameter (an enum, so the
Swagger UI at `/docs` shows it as a **dropdown** and rejects invalid values with `422`):

- `custom` (default) — self-hosted Qwen/InternVL + Tesseract OCR + Whisper transcriber.
- `mistral` — text+vision via Mistral's OpenAI-compatible endpoint, OCR via
  `mistral-ocr-latest`, transcription via Voxtral.

Selecting `provider=mistral` without `MISTRAL_API_KEY` configured returns `503`.
See [LLM Providers: Custom vs Mistral](../README.md#llm-providers-custom-vs-mistral)
for models, configuration, the model-selection rationale, and caveats.

## Shared behavior

- **Agri Gate** screening (`use_agri_gate=true`) is available on `/classify` and
  `/classify-url`.
- **Agriculture relevance + KO-eligibility gating** runs on the classification endpoints
  before subtype scoring.
- **Synchronous caps** (`MAX_DOCUMENT_UNITS=100`, media duration/size caps, request body
  cap) apply across the file and URL paths.
- **`/health`** is intentionally left **unauthenticated** so container and load-balancer
  health checks can probe it without Basic Auth.

## How `GET` differs from `POST` here

The `GET` endpoints are **read-only and side-effect free** — they describe the service
(`/`), report readiness (`/health`), or return the taxonomy (`/subcategories`). They take
no asset input and never run classification. The `POST` endpoints **accept an asset**
(file bytes or a URL) and run the classification pipeline.

For long-PDF sampling behavior and the literature behind the defaults, see the
[Long-PDF Handling section in the README](../README.md#long-pdf-handling-rationale-and-literature).
